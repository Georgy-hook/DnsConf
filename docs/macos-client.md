# План клиента macOS без GUI

Windows-реализация опубликована в [clients/windows](../clients/windows/README.md). Клиента macOS пока нет. Следующий этап — CLI и системная служба, с сохранением независимости от облачного синхронизатора DnsConf.

## Что можно использовать повторно

- `DoH`, `split_hello`, разбор HTTP и формирование DNS-ошибок из `bridge.py`: стандартная библиотека Python, TLS 1.3, проверка сертификатов и переключение между узлами NextDNS.
- Каталог `connection-routes.json`: ожидаемые маршруты для диагностики новых имён.
- Формат статуса, ограничение параллелизма и проверки, что DNS-ответ относится к исходному запросу.
- Протокольные тесты: сохранение байтов ClientHello, обязательная проверка сертификата, корректный отказ и отсутствие открытого внешнего DNS.

Текущий класс `Bridge` напрямую вызывает Windows `GetTickCount64`; его нельзя считать готовым переносимым демоном. Сначала отделить транспорт от определения загрузки ОС, файловой системы и жизненного цикла службы. Перед переносом проверить, что TLS-разделение вообще нужно в сети Mac.

## Что реализовать отдельно

| Windows | Вариант для macOS |
|---|---|
| C# ServiceBase, SCM | launchd и обработка SIGTERM |
| PowerShell + UAC | ограниченный привилегированный этап установки/возврата |
| GUID сетевого адаптера | устойчивое сопоставление сетевых служб macOS и сохранение их исходного режима DNS |
| Program Files / ProgramData ACL | защищённый каталог кода, отдельные права для статуса и резервной копии |
| GetTickCount64 | системное время загрузки и сравнение с текущей загрузкой |
| WPF, трей, NotifyIcon | команды CLI и читаемые сообщения на русском |

Предлагаемый интерфейс: `status`, `doctor`, `install`, `restart`, `restore`, `logs`. Это проект интерфейса, команды пока не реализованы. Показать различие между «процесс запущен», «DNS ответил», «маршрут совпал» и «вложение реально загрузилось».

## Условия надёжной реализации

Сохранять для каждой сетевой службы автоматический или ручной режим DNS до изменения; возврат должен восстанавливать именно этот режим. Проверять конфликт порта 53 до переключения системного DNS. Учитывать Wi-Fi/Ethernet, VPN, выход из сна, смену сети и запуск до появления интернета. Не переносить Windows hosts-пресеты в систему без отдельного выбора пользователя.

Сначала проверить новый локальный резолвер на альтернативном порту, затем установить защищённую службу, и только после успешного DNS-теста менять системные настройки. При неудаче возвращать предыдущую сеть. Повторная установка должна быть идемпотентной. Профиль NextDNS хранить локально, не включать его и резервные копии в дистрибутив.

Проверка на настоящем Mac должна включать полную перезагрузку, смену сети, сон/пробуждение, остановку процесса и возврат настроек. Загрузка GIF и ввод в компьютере Dot проверяются отдельно в авторизованном клиенте; HTTP 403 Cloudflare нельзя выдавать за проблему DNS или лечить добавлением каждого нового адреса файла.
