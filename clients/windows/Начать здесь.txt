NextDNS — менеджер подключения, обновление 28.10.2026

Запуск
Откройте NextDNS.lnk на рабочем столе в папке NextDNS.
В переносной версии распакуйте всю папку и откройте NextDNS.exe.

Трей
Менеджер показывает отдельный значок в области рядом с часами.
Windows может поместить значок под стрелку скрытых значков.
Нажатие левой кнопкой возвращает окно. Правая кнопка открывает действия.
Крестик окна и «Свернуть в трей» оставляют менеджер работающим.
«Выйти из менеджера» в меню значка завершает менеджер.
Запуск ярлыка второй раз возвращает существующее окно, без второй копии.
Менеджер показывает состояние отдельной системной службы NextDNS Bridge.

«Запускать с Windows» включает запуск в трее после входа в Windows.
Настройка относится к текущей папке приложения. После перемещения папки
откройте EXE заново и включите автозапуск из нового места.
DNS и hosts сохраняются независимо от того, открыт ли менеджер.

NextDNS Bridge
На этом компьютере прежний DNS-клиент терял соединение с NextDNS по TLS.
Bridge принимает DNS только на 127.0.0.1 и ::1 и передаёт запросы вашему
NextDNS по HTTPS/TLS 1.3. Проверка сертификата включена. Если первый узел
NextDNS не отвечает, используется второй узел того же провайдера.
Служба запускается автоматически до входа в Windows и восстанавливается
после сбоя. Меню или окно менеджера для работы DNS открывать не нужно.

Строка «NextDNS · TLS 1.3 · ответ …» показывает время ответа службы.
После перезагрузки служба сама проверяет новые имена четырёх доменных зон.
Надпись «проверено после загрузки Windows» появляется только после успешной
проверки в текущей загрузке. Это проверка DNS; GIF и трансляция проверяются
в авторизованной сессии Dot отдельно.

Для установки на другом компьютере сначала настройте его собственный
NextDNS в DNS-over-HTTPS Windows. Менеджер определяет профиль из этих
настроек; чужой профиль в переносной сборке отсутствует.

Что означает статус
«Менеджер работает» — приложение запущено.
«DNS для файлов настроен» — новые имена отвечают адресами из каталога
connection-routes.json. Это не проверка GIF, аккаунта или облачного компьютера.
«DNS-маршрут отличается» — адрес отличается от каталога; это нужно проверить.
«DNS-проверка не завершена» — не получены все ответы за ограниченное время.
Проверка выполняется в фоне при запуске и каждые пять минут. Время показано.
HTTPS-проверки известных адресов и статус локального hosts показаны отдельно.

Когда GIF не открывается
Нажмите «GIF / вложения не работают…», в том числе из меню значка в трее.
Сначала автоматически проверяется DNS. Прочитайте результат в верхней карточке.
Если служба остановлена или DNS не отвечает, используйте «Восстановить
NextDNS…» либо «Перезапустить службу…». План показывается внутри окна;
кнопка продолжения вызывает системный запрос администратора Windows.
Не требуется запускать отдельные команды или искать файл в папке.
Если проблема в Chrome, нажмите «Перезапустить Chrome…». Сохраните ввод
и закончите загрузки. Подтвердите это галочкой и нажмите «Закрыть и открыть».
Менеджер просит обычное закрытие Chrome, ждёт завершения всех его процессов
и запускает Chrome с восстановлением обычных вкладок. Окна инкогнито не
восстанавливаются. Принудительного завершения или удаления данных нет.
Если браузер не закрылся, GUI объяснит это и не покажет ложный успех.

Очистка DNS Windows не закрывает соединения браузера и не очищает его файлы.
Поэтому она не заменяет перезапуск. Если DNS не отвечает, перезапуск Chrome
сам по себе не меняет настройки DNS и не устраняет недоступность DNS-сервера.

«Веб-версия Dot в Chrome» открывает именно сайт. «Открыть приложение ChatGPT /
Dot» использует зарегистрированное Windows приложение. Это разные действия.
Настольное приложение перезапускайте через его собственное меню после
сохранения работы: менеджер не прерывает текущую работу Dot самостоятельно.

Ручные hosts находятся в сворачиваемом разделе «Дополнительно».
Пустой результат поиска адресов не означает ошибку. Он не доказывает работу
вложения. Не добавляйте случайные адреса только потому, что список пуст.
Изменение hosts по-прежнему показывает список и системный запрос Windows.
При общих правилах NextDNS новые региональные хранилища покрываются
автоматически: для каждого нового GIF отдельная запись hosts не нужна.

Cloudflare 403 в строке HTTP-проверки означает, что автоматический запрос
получил проверку сайта. Он не проверяет вход в ваш аккаунт и сам по себе
не доказывает отказ GIF. Если компьютер Dot выдаёт Retry connection,
попробуйте повторное подключение и обновление страницы. DNS-кеш не
исправляет проверку сайта. Менеджер не решает CAPTCHA и не удаляет вход.

GIF без параметра повтора воспроизводится один раз и остаётся на последнем
кадре. Это свойство самого файла, если изображение уже успешно загрузилось.

Журналы
Действия восстановления и изменения результата DNS сохраняются в
_service\run-results. Их можно найти через «Папка журналов» и убрать через
«Очистить…» → очистку истории. Активные и недавние файлы сохраняются.
Подписи и параметры ссылок на вложения в журнал не записываются.
Статус службы: %ProgramData%\NextDNSBridge\status.json.
Проверка запуска: boot-check.json; подтверждение новой загрузки:
boot-verified.json в той же папке. Журнал службы не содержит имён запросов.
Защищённая резервная копия прежней сети хранится отдельно. Для возврата
используйте «Дополнительно» → «Вернуть прежние DNS…» с подтверждением UAC.

Расширение
Новые профили импортируются на странице «Серверы» из .hosts.
Каталог connection-routes.json задаёт ожидаемые общие DNS-маршруты для
диагностики. Его изменение не применяет облачные правила NextDNS.
Нельзя считать произвольные IP постоянными: они зависят от провайдера.
